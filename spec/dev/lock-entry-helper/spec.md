# 锁班皇帝开发规格

## 产品边界

`lock-entry-helper` 是飞行门户非生产任务录入自动化工具，提供两个可独立运行和分发的本机串行工作台入口：

- `startapp.py` 在 `127.0.0.1` 启动原始串行工作台，按输入类型和日期原样录入。
- `startsmartapp.py` 在 `127.0.0.1` 启动智能串行工作台，支持页面全部已配置锁班类型，只在 `RECU_LVE-健康疗养` 与 `ALV_FD-飞行员公休（订座）` 之间按可休天数自动路由；可选启用冲突旧锁班自动解锁并单次重提。

静态工具页分发包含两个入口、后端模块和前端资源的完整应用压缩包；两个工作台的提交动作都会写入内网生产系统。

## 输入契约

- 两个工作台均支持 Excel 上传和粘贴输入；粘贴输入可以是一条或多条记录。
- 每条记录包含员工号、姓名、锁班类型、开始日期和结束日期，可选统一备注。
- `startsmartapp.py` 的 Excel 按表头读取，员工号支持“员工号”或“工号”，锁班类型支持“锁班类型”或“请假类型”；列顺序不构成业务契约。
- 员工号按六位文本校验；日期统一为 `YYYY-MM-DD` 业务日期；结束日期不得早于开始日期。
- 健康疗养或飞行员公休的智能路由记录必须在同一自然年内。其他锁班类型不读取年度配额，可按原始 APP 规则处理跨年日期。
- 白名单在提交前过滤，未入白名单的记录不得打开录入动作；输入错误必须保留错误原因。

## 工作台阶段与 API

前端阶段必须由人工分别触发：

1. “进入录入页面”调用 `/api/prepare`，启动或复用单一 worker，打开浏览器并进入飞行门户非生产任务录入页。
2. “数据健康检查”调用 `/api/check-data`，按当前固定模式解析输入并提示有效、无效数量。检查结果只提示，不构成开始录入的强制拦截。
3. “开始录入”调用 `/api/run`，在当前已打开页面中按输入顺序串行执行。
4. “终止”调用 `/api/stop`，终止 worker 并关闭其浏览器进程。

`/api/start` 是 agent 使用的全链路入口，接受与 `/api/prepare` 相同的输入，在首次登录和导航结束后直接开始录入，不替代前端的人工分步入口。`/api/status` 返回阶段、日志、进度、逐条结果和下载状态，`/api/download/result` 下载当前批次结果 Excel。

HTTP 服务只监听 `127.0.0.1`。原始和智能模式由启动入口固定，前端或 API payload 不能在运行时切换模式。

## 智能路由规则

普通锁班类型生成一个原样片段，不读取休假限制表，不替换锁班类型。

健康疗养或飞行员公休按以下顺序预检：

1. 输入员工号并校验页面识别出的员工号和姓名。
2. 依次选择输入类型和另一类型，等待 `#nonproductionTaskRulesTipsDiv` 刷新。
3. 从 `.hDiv table` 按表头读取字段，从 `.bDiv table` 读取数据行；必需表头是“休假类型、年份、休假天数、锁班天数、解锁天数、可休天数”。
4. 只读取输入开始日期所在年份的唯一数据行，以“可休天数”作为当前额度；缺年、重复年、列数异常或非整数额度均视为预检失败。
5. 填写原始起止日期并读取页面 `#lockDays1`；页面锁班天数必须与连续自然日计算一致。
6. 输入类型优先使用，最多分配到其可休天数；剩余连续尾部日期分配给另一类型。
7. 两类可休天数合计不足时不生成任何提交片段，整条记录归档为“额度不足”。输入类型额度为零但另一类型足够时，整段使用另一类型。

飞行员公休页面显示的“一年一次订座”提示不构成脚本额外推算字段。智能 APP 按 owner 明确口径使用当前年度“可休天数”路由，门户返回的其他业务冲突仍按实际结果归档，不绕过冲突。

普通 `ALV-年假（公休假）` 与 `ALV_FD-飞行员公休（订座）` 是两个不同页面代码。`ALV` 按普通类型原样提交，不参与健康疗养额度互换。

## 提交链路

- 用户设置输入后点击“进入录入页面”，worker 打开浏览器、等待扫码并导航到非生产任务录入页；自动导航失败时日志提示人工进入目标页面，不新增页面健康检查按钮。
- 结果 Excel 只在“开始录入”后解析出至少一条有效记录时创建。
- 每个实际片段重新填写员工号、锁班类型、起止日期和备注，并触发页面依赖的 input/change/blur 事件。
- 页面锁班天数必须等于片段计划天数，之后才允许点击“下一步”。
- 查询结果必须按当前片段的员工、姓名、锁班类型和日期范围精确归属，不能把相邻人员或其他页面结果串写。
- 当前片段成功后回到录入页处理下一片段；未启用冲突回退或回退后仍失败时，停止该原始记录，剩余片段写为“未执行”，批量模式继续下一条原始记录。
- 首段成功、后段失败属于部分完成，结果中必须同时保留已成功片段和失败片段；不得自动重跑已成功片段。

## 冲突回退

- 启动时由用户明确选择是否启用。未启用时维持原有冲突归档行为。
- 冲突回退适用于所有实际提交片段，不改变普通类型和两类智能休假的路由规则。
- 从提交结果页进入“锁班查询”，按员工号筛选全部“已锁”分页；查询表按表头读取，省略文本优先取单元格 `title`。
- 候选必须同时满足员工号一致、状态为“已锁”、旧记录自然日区间与当前冲突片段区间重叠，并且全分页恰好一条。零条或多条都不得解锁。
- checkbox 的 value、旧记录序号、录制时行号和 accessible name 不构成定位依据。唯一候选确定后，只在该行 DOM 内查找可用 checkbox。
- 解锁前必须把旧行完整字段写入结果 Excel；保存失败时不得点击解锁。门户解锁作用于旧整行，不拆分相交日期。
- 解锁原因弹窗和结果提示弹窗各确认一次；只有结果文本明确显示成功且重新查询确认旧行不再“已锁”，才允许回录入页。
- 原请求只重提一次。重提仍冲突或失败时记录并跳过当前原始记录，不继续解锁第二条。
- 新锁班继续使用用户统一备注或门户按类型生成的默认锁班原因，不写入旧记录摘要。

## 输出与恢复

- 两个工作台都在 `results/<runId>/` 新建结果 Excel，每处理一条或一个实际片段立即落盘，不回写输入 Excel。
- 智能结果表保留原始序号、片段序号、输入类型和日期、实际类型和日期、计划天数、两类预检额度、门户结果、冲突、匹配证据、尝试次数、冲突回退状态和解锁旧行结构化字段。
- 解锁成功后的重提结果在 Excel“备注”写入“已解锁”以及旧记录的锁班名称、锁班原因、开始日期和结束日期；不把这段摘要写入门户锁班原因。
- 合计额度不足或预检失败使用片段序号 0 归档，表示未执行生产提交。
- 中断后以结果文件中已落盘记录为完成证据。恢复前必须排除已成功片段，避免重复生产提交。
- openpyxl 是智能 APP 的必需依赖；缺少结果写入能力时智能 APP 直接停止，不允许无证据提交。
- 一批完成或发生可归档失败后，worker 和浏览器继续保留，前端可重新选择 Excel 或粘贴下一批并复用登录会话；只有 `/api/stop`、服务退出或浏览器自身关闭才结束会话。
- 前端按原始记录或智能实际片段逐条显示员工、输入类型和日期、实际类型和日期、处理状态、门户结果、重试/回退信息和备注。结果区与日志区默认跟随最新内容；用户向上滚动后停止自动置底，回到底部后恢复跟随。
