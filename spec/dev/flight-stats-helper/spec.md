# 飞行经历查询开发规格

## 产品边界

`flight-stats-helper` 是可独立下载运行的 Python + Playwright APP。用户启动 `start.py` 后，在本机工作台输入 Excel 或粘贴数据，人工扫码登录飞行门户，按人员和日期区间逐人查询飞行经历页面，并把页面当前可见表头和同行数据保存到 Excel。

工作台也提供本机 HTTP API：`/api/start` 保留 agent 使用的全链路启动查询，`/api/prepare` 启动浏览器并进入查询页后等待或复用已完成的浏览器会话，`/api/check-data` 按既有输入规则检查有效数据，`/api/run` 在人工点击后开始分步查询，`/api/status` 读取状态，`/api/stop` 终止当前查询；查询完成后 worker 和浏览器会话继续等待下一批输入，只有 `/api/stop` 才关闭浏览器；服务只监听 `127.0.0.1`。

## 输入契约

- Excel 第一行按表头读取员工号、姓名、开始日期和结束日期；姓名可为空。
- 粘贴输入按行读取员工号、姓名和日期区间，日期使用 `YYYY/MM/DD` 或 `YYYY-MM-DD`。
- 查询范围为“飞行时间+起落数”“飞行经历+起落数”“左座经历+起落数”“全部数据”复选项；前三项可组合，输出对应经历和起落总数；全部数据为全选快捷项，输出页面全部可见字段。
- 无效记录进入输入错误，不进入门户查询；重复员工号只处理一次。
- 源 Excel 只读，不覆盖；结果写入本次运行独立目录。

## 自动化链路

- 每次工作台启动创建新的 worker、Playwright browser、context 和 page；同一工作台会话内的下一批查询复用它们。
- 浏览器打开登录页并点击扫码登录，用户完成扫码后进入飞行经历页面。
- 进入飞行经历页面后沿用旧逻辑自动选择“按天查询”。
- 前端分步流程中，进入页面后等待下一次按钮操作；数据健康检查只自动提示既有输入有效性结果，不改变后续查询条件，也不要求人工确认检查结论。
- `/api/start` 保留 agent 的全链路语义，直接沿用原有进入页面后读取有效数据并逐人查询的顺序。
- 每批查询完成后 worker、browser、context 和 page 继续等待下一批；重新准备 Excel 或粘贴数据时复用同一登录会话，只有 `/api/stop` 才关闭它们。
- 查询按天设置员工号和日期，读取页面实际日期后点击查询。
- 结果按当前可见表头和匹配员工号的同行单元格读取，不使用固定列号；页面表头结构异常或员工不匹配时记录失败。
- 查询成功或失败后立即发送逐人结果事件；指定范围包含对应经历字段和“起落总数”，全部数据包含页面全部可见字段，前端按人员逐行展示。
- 单条查询失败写入失败状态并继续后续人员；浏览器关闭或用户终止时停止后续查询。

## 输出契约

- 每次运行同步生成原版和去分钟版两个 Excel。
- 原版保留页面原值；去分钟版仅把“飞行时间”“飞行经历”“左座经历”的 `H:MM` 转成小时部分。
- 两个文件保持相同字段、行数和查询状态；页面不存在的字段不创建。
- 每人完成后原子保存，失败行保留员工号、姓名、日期、状态和错误说明。

## 文件职责

- `start.py`：唯一启动入口，创建 loopback 服务并打开浏览器。
- `flight_stats/input_data.py`：输入归一化和 Excel/粘贴解析。
- `flight_stats/portal.py`：登录、导航、日期设置、查询和动态表格读取。
- `flight_stats/exporter.py`：原版/去分钟版 Excel 原子写入。
- `flight_stats/runner.py`：worker 生命周期、逐人循环和事件。
- `flight_stats/server.py`：本地 HTTP、分阶段命令、agent 全链路入口、单 worker 启停、状态和结果下载。
- `web/`：工作台页面。

## 运行与维护

- 依赖：Python 3.10+、Playwright、openpyxl；首次使用需安装 Chromium。
- 运行：`pip install -r requirements.txt`、`playwright install chromium`、`python start.py`。
- 门户、账号和页面改版只能在真实内网环境验证；仓库测试使用输入、表格解析、导出和假 worker。
