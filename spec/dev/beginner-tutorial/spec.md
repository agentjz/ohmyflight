# 菜鸟教程开发规格

菜鸟教程是工具首页第一项，面向南货航新员工，提供飞行人员从进入公司、转机型、技术等级变化到教员/考试员和各项运行资质生命周期的可查询知识库。它不是开发者手册、Agent Skill 或原始 Word 文件阅读器。

## 知识边界

当前正文只使用两本已核对的现行手册：

- 《飞行人员训练大纲》R03-01 V6
- 《飞行技术管理手册》R01-08 V1

培训皇帝和备忘录只可作为发现问题的业务线索，不能替代两本手册的证据。所有条目必须经过语义审计后写入 APP 内容目录，机械提取结果不得直接发布。

## 内容模型

正文源文件位于 `src/tool/app/beginner-tutorial/content/`：

- `knowledge.json`：手册来源索引、模块目录和可检索的结构化记录。
- `special-categories.md`：Z/R/S、E类和教员/考试员等特殊分支的语义边界。

`knowledge.json` 的模块目录和顺序由知识源数组声明，页面按数据动态生成，不用测试锁定模块数量、顺序或具体条目。当前按手册语义组织为副驾驶技术等级、机长技术等级、教员与考试员、资质总表、重新获得资格训练、关键数字；技术等级按副驾驶 A1→A2→B→C→D、机长 B→C→D 及 Z/R/S 特殊分支展示，恢复模块独立维护。

普通记录保留一行完整业务对象，字段包括进入条件与动作、保持与失效触发、适用对象、依赖、证据状态和手册来源。重新获得资格记录在一个失效原因对象内使用分段清单，完整呈现触发、时间分档、训练、检查、结果分支、降级和记录要求，避免把一个流程拆成难维护的小卡片。

## 构建与页面

构建脚本只从 APP 内容目录读取知识源，解析 `sourceIds` 为手册名称、版本和章节，生成 `dist/tool/beginner-tutorial-data.json`。页面使用菜鸟教程专属 `main.ts` 和 `tutorial.css`，不复用开发者页面、文档库或 `skill-*` 结构。

页面提供模块导航、搜索和来源小字。技术等级、教员/考试员、资质和关键数字使用表格；重新获得资格使用完整的分段恢复条目。页面不提供合并下载，也不把 Agent 的阅读流程、版本比对和维护约束显示给新员工。

## 语义审计要求

维护前完整阅读两本原始手册，按业务语义确认适用对象、起算事件、时间单位、经历字段、检查顺序、签注/聘任/发布和失败后果。训练大纲描述课程如何实施，技术管理手册描述技术等级、检查、岗位聘任和资质管理；两本手册出现不同字段时并列保留，不自行合并。

手册有意留空或当前证据不足的条目必须标记为“条件未完整给出”，不得用备忘录摘要、局方惯例或经验补写。来源显示到手册和章节，原始 Word 手册仍是办理业务时的最终依据。

## 验收

- `npm.cmd run build` 生成页面脚本、专属样式和知识 JSON。
- `npm.cmd run typecheck` 通过，结构化类型不扩大隐式 any。
- 全量 `npm.cmd test`、`npm.cmd run verify` 通过。
- 人工检查桌面和移动页面：知识源中的业务入口可访问，恢复入口独立，长流程可完整阅读，来源可追溯，未出现维护说明或手册长文混排。
