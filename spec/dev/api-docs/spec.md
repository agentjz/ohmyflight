# API 文档开发规格

## 定位

API 文档是跨系统 HTTP 接口的事实导航和真实单次调试器，不是批量业务工作台。当前目录包含飞行门户的飞行经历查询、飞行人员锁班和飞行人员信息查询三类模块；后续 OA、天健等系统继续以独立模块加入，不把业务工作台合并进文档。

## 事实源

`public/tool/app/api-docs/catalog/index.json` 只负责模块索引；其引用的模块 JSON 是 URL、方法、Headers、参数、响应契约和内部请求链路的唯一事实源。静态页面、Python 后端和 Markdown 导出必须直接消费同一目录，不分别维护接口字段表。

飞行人员信息模块按四个分组展示：基础信息、技术等级、运行资格、训练检查记录。当前五个业务 endpoint 为基础信息、技术等级、运行资格、培训记录和训练经历；培训记录的批量分页属于飞行人员信息查询（皇帝版）工作台，API 文档只执行用户指定的单页真实请求。

## Cookie 生命周期

- `POST /api/session`（或兼容路由）验证当前页面提交的 Cookie Header/cURL，凭据只存在后端内存。
- 验证成功后页面显示可复制的规范化 Cookie Header；刷新、重新打开或主动清除都必须清空当前会话，不得从 localStorage、静态文件或旧保活状态恢复。
- 保活使用 1-60 秒随机只读请求；登录页、HTTP 错误或页面契约异常会清空会话并停止请求。
- 状态、Markdown、原始响应和导出不得包含 Cookie 值。

## 单次执行

页面只提交完整 endpoint ID 和业务参数，基础地址、路径和方法来自目录。后端按 `systemId` 选择适配器，区分 HTTP 状态、登录失效、解析错误和业务返回；HTTP 200 不单独代表业务成功。结构化表格、原始 JSON/HTML、响应 Headers 和状态码同时返回。

## 导出

“导出 Markdown”不依赖本地后端，读取当前已加载的静态目录生成一个机器和人类都可读的单文件；不得包含 Cookie、会话状态、真实响应或人员数据。原始目录 JSON 作为附录保留全部条件字段、动态选项、派生来源和响应契约。

## 验证

单元测试和静态测试只保护目录加载、参数构造、解析、状态生命周期和交付连通性。涉及真实接口契约、Cookie、动态参数或响应解析的修改，必须用 owner 授权的真实 Session 与真实业务样例做一次端到端只读验证；没有真实验证只能标记未验证，不能宣称有效。
