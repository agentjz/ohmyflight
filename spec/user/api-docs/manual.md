# API 文档使用手册

## 查看接口事实

从工具首页顶栏打开“API 文档”。该入口不占用工具卡片；左侧“Cookie 管理”用于查看飞行门户认证方式，展开“飞行门户”后只有“飞行经历查询”和“飞行人员锁班”两个接口。

接口正文依次展示：

- 门户导航地址和真实 HTTP 请求地址
- 请求方法、Cookie 和 Headers
- 全部 Query/Form 参数及自动派生来源
- cURL 和 Python 调用示例
- 响应状态、字段和脱敏示例
- 业务接口背后的完整内部请求链路
- 当前已确认的技术说明

内部请求链路全部直接展开。每个环节都显示业务名称、技术 ID、方法、完整 URL、参数、用途和响应契约，无需逐项点击。

“Cookie 管理”页提供总目录 `./catalog/index.json`，每个接口顶部提供对应模块 JSON。页面与本地执行器都读取这些 JSON；需要交给 AI 或程序分析时，可直接使用该结构化事实源，不必从页面文字反推接口。

在线页面无需启动后端即可查看全部文档。右侧 Cookie、参数和发送按钮保持灰色，不影响文档和示例阅读。

## 导出给人或语言模型

点击页面顶栏“导出 Markdown”，浏览器会下载单个 `watchdog-api-docs.md`。该文件不依赖网页资源，可以直接用文本编辑器阅读，也可以交给只接受纯文本文件的语言模型分析。

Markdown 前半部分按人类阅读顺序展示认证、业务接口、Headers、参数、响应、内部请求链路和技术说明；末尾附上模块索引及两份原始目录 JSON，用于保留条件字段、派生来源、动态选项和响应契约。导出只读取静态接口目录，不包含粘贴的 Cookie、会话状态、真实响应或人员数据，也不要求先启动本地后端。

## 启动本地单次调试

需要真实单次调试时，在仓库的 `public/tool/app/api-docs/` 目录安装依赖并启动：

```powershell
python -m pip install -r requirements.txt
python start.py
```

浏览器会打开与在线页面相同的界面。关闭终端或按 `Ctrl+C` 后，本地执行器和内存中的 Cookie 一并清除。该调试器只用于单次真实请求，不替代独立的飞行经历查询（皇帝版）和锁班皇帝（新）。

## 管理 Cookie

在已登录飞行门户的浏览器中打开 F12 Network，对任意已登录请求执行 Copy as cURL；也可以复制完整 Cookie Header。进入“Cookie 管理”，粘贴后点击“验证 Cookie”。

工具只读取 `JSESSIONID` 和 `iebJSid`。验证成功后，规范化 Cookie 会显示在当前页面下方并可直接复制；它不会写入文件或浏览器持久化存储。刷新或重新打开页面时，本地执行器会立即清除旧 Session、停止旧保活并回到“Cookie 未验证”，当前页 Cookie 同时消失。锁班类型不会在验证时加载，而是在进入“飞行人员锁班”接口后从门户录入页读取。

验证成功后，本地后端每隔随机 1-60 秒访问一次飞行经历查询页，以保持并确认登录状态。该请求不带员工号、不查询人员数据，也不提交锁班。页面持续显示最近验证时间；临时网络异常会继续重试，门户返回登录页时显示 Cookie 已失效并自动禁用真实请求。

## 发送单次请求

选择接口后在右侧填写业务参数。日期、月份、时间和日期时间使用对应的浏览器控件；锁班类型使用门户当前动态下拉项；姓名、部门、类型名称、日期拆分标记、防缓存参数和锁班天数由本地执行器取得或计算。

点击“发送真实请求”会立即访问飞行门户，不是 Mock。响应可切换四种视图：

- 表格：摘要和适合人工阅读的结果表
- 结构化 JSON：解析后的字段与数据行
- 原始响应：门户返回的原始 HTML 或 JSON
- Headers：已移除 Cookie 的响应头

飞行人员锁班是写操作，单次点击即提交一次。调试器不自动通过、不做额度智能互换、不解锁冲突记录，也不批量执行。HTTP 200 仍可能对应业务冲突或失败，应同时查看结构化结果和原始响应。

门户锁班结果使用分离的表头区和数据区。当前页面会把普通结果与冲突结果分别解析为表格；无论结构化解析是否成功，“原始响应”都会保留门户返回内容，便于核对页面变化。
