# 菜鸟教程维护

菜鸟教程是员工可见的独立 APP，不是开发者文档、原始手册阅读器或 Agent Skill。它把两本现行手册中影响成长、权限和资格恢复的核心规则呈现为结构化、可检索的业务知识，正文必须以语义审计结果为准。

## 经验沉淀原则

每次完成原始手册探索或教程语义复核后，都要回看本 Skill，只沉淀能让下一次核对明显更快、更准的非显然经验：稳定的章节地图、有效的抓取方法、高风险关键词、容易混淆的字段和曾导致范围误判的判断原则。

- 先合并、修正或删减已有经验，再考虑新增；不要按任务时间顺序追加聊天结论，不写变更日志。
- 只保留可跨版本复用的找法和判断法。具体版本数字、人员条件和当前业务结论写入教程与`spec/`，不在 Skill 维护第二份事实源。
- 新经验必须能防止一种真实错误或减少一轮重复探索；课程细目、偶然样例、完整原文和已被一般原则覆盖的提醒不进入 Skill。
- 手册换版后先验证章节地图和关键词是否仍有效，失效经验直接替换或删除，不能让 Skill 只增不减。

## 依据与边界

- 只使用用户提供的《飞行人员训练大纲》和《飞行技术管理手册》现行文件；先确认文件名、版本、修订记录和适用机型。
- 运行手册不属于本教程范围；培训皇帝、备忘录和历史参考 Markdown 只能帮助定位问题，不能作为正文证据。
- 原始 Word/PDF 是最终依据。教程来源只写手册名称、版本和章节，不能用“请看第14章”“按对应提纲处理”等空泛跳转替代具体条件。
- 搜索或批量提取只用于定位候选段落、表格和章节。写入前必须阅读命中位置的完整上下文，并逐条核对适用对象、起算事件、时长/经历字段、检查顺序、合格与失败分支、降级/停飞、签注、聘任、审批、发布和系统入库。

## 用工具读取原始手册

1. 先用文件扫描确认输入文件的完整名称、大小、版本号、修订号和日期，只读取用户指定的现行文件；同目录存在副本、旧版或运行手册时不得按文件名相似度猜选。
2. 优先用`python-docx`读取段落数、表格数、非空段落、表格行列和样式。若文件内部实际为宏启用Word内容、`python-docx`拒绝读取，或必须保持段落与表格的原始交错顺序，改用只读OOXML解析；仓库现有`.agents/skills/compare-manuals/scripts/extract_manuals.py`的`word_units()`可按文档顺序输出`index`、`kind`、`style`和`text`。
3. 先用样式和目录建立“章节—小节—正文/表格”边界。目录和正文通常会重复出现同一标题，不能把目录页码行当正文证据；定位到正文标题后，读取该业务对象直到下一同级标题，而不是只读取搜索命中的一句。
4. 搜索只负责定位。每个候选命中必须向前确认标题、适用对象和进入条件，向后读完训练/经历、检查、合格与不合格、记录和审批；命中表格时读取完整表头、相关行、合并单元格重复值和紧随表格的注释。
5. 为每条拟写事实保留“手册—版本—章节/小节—Word顺序索引—完整原文上下文”的审计记录。审计记录可以是临时只读输出，不提交原始手册、全文抽取结果或个人数据。

## 两本手册的核对地图

章节号是高价值起点，不是永久事实；每次换版先用目录和正文标题重新确认。

- 《飞行人员训练大纲》主要回答“训练怎么实施”：第5章副驾驶转机型、第7章机长转机型、第9至12章教员考试员、第14章重新获得资格、第18章以后各类专项训练。带`*`且正文写明有意留空的章节不能据标题补规则。
- 《飞行技术管理手册》主要回答“等级、检查、权利和管理如何生效”：第3章训练、等级和恢复，第4章检查标准，第5章在座与航线资格，第6章聘任，第7章执照，第9章档案；附录A看型别教员，附录B看考试员，附录D/G看胜任力问题，附录E看EBT，附录H看资质审批发布，附录K看航线飞行教员。
- 同一业务必须双向读：训练大纲给课程、课时、科目和训练结果；技术管理手册给经历门槛、技术检查、运行限制、聘任和恢复；附录给专项的选拔、考核、终止或发布。任何一本都不能单独替代完整事件链。

## 高价值搜索锚点

先搜结构词确定边界，再搜业务词和数字定位候选，最后阅读完整上下文。推荐按组组合查询，不要只搜一个数字。

- 结构词：`修订记录`、`有效条款清单`、`目录`、`有意留空`、`适用范围`、`进入条件`、`资格获取`、`资格保持`、`过期后的办理`、`训练记录保存`。
- 经历和位置：`航线运行经历`、`操作驾驶员`、`PF`、`PM`、`左座`、`右座`、`昼间`、`夜航`、`航段`、`飞行`、`起飞`、`着陆`、`起落`、`人工飞行`、`复飞`。
- 检查和结果：`航线技术检查`、`熟练检查`、`实践考试`、`年度航线检查`、`带飞能力检查`、`补充训练`、`增加经历`、`不合格`、`再次检查`、`终止训练`、`停飞`、`降为`、`退回原机型`。
- 生效和权利：`签注`、`聘任`、`批准`、`资质通告`、`发布`、`入库`、`不得参加运行`、`恢复相应运行资格`、`自动恢复`。
- 数字锚点：`90个日历日`、`120天`、`100小时`、`25小时`、`4次飞行`、`4个航段`、`4个起落`、`18分钟`、`24分钟`、`6个月`、`12个日历月`、`24个日历月`、`36个日历月`、`60天`、`90天`、`210个日历日`。这些只是发现候选规则的入口，必须连同对象、单位、起算事件和失败分支重新核对，不能直接复制。

## 核心内容取舍

教程的核心是会改变人员状态或工作权限的事件链：谁可以进入，必须完成什么训练和经历，由谁检查，怎样取得技术等级、教员考试员权利或运行资质，怎样保持，失效后怎样恢复，失败后是否停飞、降级或退出。

- 主线必须覆盖新雇员、转机型、副驾驶等级、机长等级、教员考试员、主要运行资质和按原因拆分的恢复路径；替代发展通道或特殊身份如果改变岗位权限，也应明确说明，但不得硬接入普通晋升链。
- 课程逐项知识点、设备清单、题库、教员姓名、普通记录保存细节通常不进入教程；只有它们直接决定进入条件、课时、考试、权限生效或恢复结果时才保留。
- 反向扫描手册所有非空章节，对未纳入内容明确判断“核心主线、特殊例外或范围外细节”。章节非空不等于必须加入教程，章节留空也不能据标题推导规则。

## 极高风险语义

以下字段必须逐字核对原文的限定词和作用范围，任何一个都不能靠常识补齐：

- 数量与单位：飞行时间、航段、飞行次数、起飞、着陆、起落、训练课、课时、人工飞行分钟分别记录；“一次飞行”不能改写成“一个航段”或“一个起落”。
- 角色与场景：PF/PM、操作驾驶员/辅助操作驾驶员、左座/右座、昼间/夜间、进近类型、着陆/复飞、带飞/检查分别记录；原文未绑定的组合不得自行绑定。
- 范围限定：特别检查`至少`、`不多于`、`不超过`、`且`、`或`、`其中`、`同一级`、`每个执勤位置`、`如适用`等词。不能把“同一级全部航段”扩大成“全部检查”，也不能把某机型或某岗位条件推广到全员。
- 时间语义：区分连续日、日历月、基准月、到期前窗口、起算事件和第一个失效月；90天近期经历、航线飞行间断、复训逾期和检查不合格是不同触发原因。
- 结果链：训练合格、考试合格、检查合格、执照签注、聘任、资质审批发布和系统入库是不同事件；必须读完首次失败、补训/增加经历、再次检查、最终停飞或降级的全部分支。
- 多手册交叉：两本手册出现不同字段时按各自适用阶段并列保留；看似冲突时回到上下文确认对象和起算事件，不取较大值、不取较严值，也不合并成一个新规则。

完成语义审计后，按“人员对象 × 触发事件”建立覆盖矩阵，并做双向检查：每条教程记录能回到完整手册上下文；每个与人员状态或权限有关的手册核心事件，在教程中有记录、明确列为特殊例外，或有可解释的范围外结论。只有核心链闭合且没有范围扩大、单位偷换、失败分支缺失时才修改正文；如果剩余内容只是课程细目，不得为了显得完整而扩写。

## 内容入口

知识源位于 `src/tool/app/beginner-tutorial/content/`：

- `manifest.json`：知识库信息、来源文件和模块文件顺序。
- `sources.json`：两本手册的版本和章节来源索引。
- `modules/`：按转机型、技术等级、教员考试员、资质、恢复和关键数字拆分的结构化记录。
- `special-categories.md`：Z/R/S、E类、教员考试员例外和手册留空项等不适合统一结构的正文。

当前页面按手册语义组织副驾驶技术等级、机长技术等级、教员与考试员、资质总表、重新获得资格训练和关键数字；这只是当前知识源的组织结果，不是固定数量、固定顺序或永久目录。新增或调整业务对象时，以知识源中的模块、记录和来源为准，不另写页面白名单。不要把“人员路径”或“证据边界”这类维护说明恢复为员工知识模块。

普通记录保持一个完整业务对象，字段至少包含 `status`、`category`、`audience`、`summary`、`action`、`lifecycle`、`sourceIds`。转机型使用顺序分段，普通等级和资质使用可展开详情，复杂恢复使用结果分支，自由说明使用Markdown，不强制所有业务对象套同一表格。

权威恢复规则只维护、只完整展示一份。等级、资质和转机型记录只有在它能直接回答“当前对象失效后怎么办”时才使用 `recoveryRecordIds`；构建时解析为标题、摘要和稳定目标，不复制正文。

超文本取舍必须克制：不为了图谱完整性链接A1/A2成长节点、转机型路径或其他泛化关联，不建立反向引用，不在恢复规则之间继续串联关系。近期经历不足、复训/熟练检查逾期、熟练检查不合格等触发事件仍分别保留；链接减少重复或缩短找到处理办法的路径，才有保留价值。新增每条链接前先问：它是否直接对应当前记录的失效原因？如果不能明确回答，删除链接而不是补上下文。

重新获得资格训练必须按失效原因独立成条，直接写出触发条件、失效时长分档、理论/训练器/模拟机/航线经历、检查和实践考试、补训次数、失败后的降级或停飞及记录动作。不能只写“按第14章处理”。

## 更新流程

1. 阅读 `manifest.json`、`sources.json`、受影响的 `modules/` 文件和关联Markdown，列出受新版本影响的模块、记录和来源。
2. 用 `python-docx` 或等效结构化读取完整 Word 段落、表格和附录；先按章节定位，再逐条语义审计。两本手册出现不同数字或字段时并列保留并说明适用阶段，不自行合并。
3. 更新 `sources.json` 的手册版本和章节，再更新对应模块记录；删除过期事实，不保留兼容旧口径的隐藏字段。
4. 将可比较的等级、资质、周期、依赖和证据写入 JSON；只有无法用统一字段表达且有完整手册依据的业务正文才写入 Markdown。员工可见正文不得出现 `partial` 等英文维护术语。
5. 检查每个 `sourceIds` 都能解析到 `sources.json`，每个 `recoveryRecordIds` 都指向 `recovery` 模块中的权威记录，每条记录都有适用对象和来源；检查恢复流程的成功/失败分支闭合。
6. 同步 `spec/dev/beginner-tutorial/spec.md`、`spec/user/beginner-tutorial/manual.md` 和相关测试，不把聊天过程或未来计划写入文档。
