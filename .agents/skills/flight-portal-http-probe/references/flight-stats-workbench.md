# HTTP 飞行经历工作台约束

## 产品边界

- `http-flight-stats-helper` 与 Playwright 版 `flight-stats-helper` 并列，旧 APP 的代码、入口和行为保持不变。
- 用户维护已登录门户会话。工具只解析目标 Cookie，不实现登录、扫码、验证码或 Cookie 刷新。
- 查询只读；任何录入、撤销、审批或状态修改都不属于本业务授权范围。
- 当前产品严格串行，不提供并发数、并发开关或 worker 池。

## 输入与预设

- 输入沿用旧工具：员工号、可选姓名、开始日期、结束日期；重复员工只处理第一次。
- 数据健康检查只提示有效性，不形成确认门槛。
- 前端保留四个预设：飞行时间+起落数、飞行经历+起落数、左座经历+起落数、全部数据。
- 前三项可以组合，每项都包含起落总数；全部数据是全选快捷项。
- 每名员工只请求一次完整结果，预设只筛选输出列，不按范围重复请求门户。

## 执行与归属

- 所有人员严格按输入顺序查询，复用凭据验证后保留的单个 Session。
- 响应按动态表头解析，并精确匹配当前员工号；输入姓名非空时同时校验姓名。
- HTTP 200、有表格或有一行都不能单独代表成功。
- 登录失效后停止后续查询，未查询人员写明原因，不无限重试。
- 查询完成事件逐人展示，向上滚动暂停自动置底；最终结果按原输入索引归位。

## 结果

- 所有请求结束或终止后一次性生成原版和去分钟版 Excel。
- 去分钟版只转换飞行时间、飞行经历和左座经历的 `H:MM`，其他字段保持原值。
- 原版与去分钟版字段、行数和顺序一致。
- 结果目录从 Git 和独立下载包排除，真实输入、人员和结果不进入仓库。

## 本地工作台

人工阶段为验证凭据、数据健康检查、开始查询、终止。agent 保留 `/api/start` 全链路入口；它复用用户已有登录态，不模拟登录。

模块职责：

| 模块 | 职责 |
|---|---|
| `credentials.py` | 解析目标 Cookie，不回显凭据 |
| `input_data.py` | Excel/粘贴输入归一 |
| `portal_client.py` | 会话验证、查询参数、动态表格和身份归属 |
| `exporter.py` | 预设筛选和最终双文件 |
| `runner.py` | 串行循环、中断、事件和原顺序结果 |
| `manager.py` | 内存 Session、阶段、线程和下载状态 |
| `server.py` | loopback API 与静态资源 |
| `web/` | 人工分步工作台 |

## 维护顺序

1. 用查询页验证登录态和 form。
2. 用一个授权样例确认动态表头和身份归属。
3. 接口变化时先更新脱敏 fixture 和失败测试，再改客户端。
4. 用 owner 原始 Excel 回放时只输出汇总、耗时、字段和一致性，不打印人员数据。
5. 运行局部测试及仓库 build、typecheck、test、verify，并检查结果目录、zip、敏感信息和 BOM。
