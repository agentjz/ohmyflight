# HTTP 锁班工作台实现约束

## 产品定位

`http-lock-entry-helper` 是与旧 `lock-entry-helper` 并列的独立本地 APP。用户自行维护 IEB 登录态并粘贴凭据；APP 用 HTTP 批量执行 Excel 或粘贴数据中已经填写好的逐行要求。

它不是重新包装门户单人表单。不能要求用户为整批再选一次锁班类型、日期或人员。每条记录自己的类型、日期、时间和备注才是执行输入。

页面名称使用“锁班皇帝（新）”。同类后续纯 HTTP APP 的目录和技术标识也使用 `http-` 前缀；旧 APP 不改名。

## 人工分步

前端保持人工控制，并把动作与状态清楚分开：

1. 粘贴登录凭据并点击“验证凭据”。后端解析 cURL 或 Cookie Header，GET 录入页并返回会话是否有效、当前类型数量和验证时间；不回显 Cookie。
2. 上传 Excel 或粘贴批量数据。
3. 点击“数据健康检查”，只提示有效/无效数量和逐条原因，不强制确认，也不锁住开始按钮。
4. 点击“开始录入”，按输入顺序串行执行。
5. 点击“终止”才中断当前任务并清理运行状态。HTTP Session 在批次结束后继续保留，可直接换下一批输入。

不再设置“进入录入页面”按钮，因为纯 HTTP 运行时没有需要人工进入的浏览器页面；它对应的明确动作是“验证凭据”。不要把验证凭据、数据检查和开始录入合成一个自动启动。

页面提供默认不勾选的“提交成功后直接通过并锁班”。未勾选时保持提交后待审批；勾选时每个片段仍严格串行执行“提交并保存待审批结果 -> 通过 -> 查询确认已锁且不再待审批”。通过失败要明确提示待审批记录已经生成，不能把两步混成一个不可核对结果。

## 凭据导入

至少接受：

- Chrome/Edge F12 Network 的 Copy as cURL 文本。
- 完整 `Cookie: name=value; ...` Header。
- 仅 Cookie 值文本时，必须由明确格式解析，不按空格或引号猜测。

解析器只提取目标域的 Cookie，不执行用户粘贴的 cURL 命令，不信任其中的 URL、方法或 Body。后端将凭据装入独立 Session，验证后只向 `https://ieb.csair.com` 请求。

凭据只存当前后端进程内存。状态 API 返回“是否已验证、验证时间、类型元数据版本摘要”，不返回 Cookie、原始 cURL 或请求 Header。浏览器前端不把凭据写 localStorage/sessionStorage；刷新后需要重新粘贴是可接受的明确行为。

## 输入契约

沿用旧版 Excel 和粘贴习惯：员工号、姓名、锁班类型、开始日期、结束日期，以及可选备注。新增时间能力时以显式列或粘贴字段扩展，不改变已有无时间输入的默认行为。

建议稳定业务模型包含：

```text
employeeId
expectedName
lockTypeInput
timeMode
startDateTime
endDateTime
yearMonth
selectedDays
remark
sourceRow
```

规则：

- 员工号按六位文本处理，不能因 Excel 数值读取丢失前导零。
- 日期和时间在读取边界归一为明确的业务文本，不用 UTC 转换。
- 类型输入支持代码、`代码-名称` 或门户完整标签，最终只用当前动态列表的 code 和 metadata。
- 不提供自定义时间时维持门户默认值：CRM 为 `08:30-16:30`，其他类型为 `08:59-19:59`。
- 模式 1 使用连续起止日期时间；模式 2 使用月份、一个或多个日号以及统一起止时分。
- 每行备注优先于统一备注；两者都为空时生成门户当前默认原因。备注最终遵守门户 60 字符 UI 约束。
- Excel 姓名只用于一致性提示；门户员工校验返回的姓名和部门用于提交。

数据健康检查复用实际解析函数和动态类型元数据。检查结果只提示，开始录入时仍重新解析当前输入，防止上传内容变化后沿用旧结果。

## 模块职责

模块边界按变化原因划分，不把 Cookie、Excel、HTTP、智能额度、状态机和页面渲染塞进一个文件：

| 模块职责 | 内容 |
|---|---|
| 凭据解析 | cURL/Cookie Header 解析、脱敏摘要 |
| Session | Cookie 装载、公共 Header、凭据验证、失效识别 |
| 门户元数据 | 录入页动态类型、默认原因模板、时间限制标记 |
| 门户客户端 | 员工校验、额度、提交、查询、状态动作 |
| 输入 | Excel/粘贴解析、日期时间归一、白名单 |
| 智能路由 | 仅 RECU_LVE/ALV_FD 额度互换和片段生成 |
| 结果解析 | 普通结果、冲突、查询分页、精确归属 |
| 运行编排 | 串行执行、中断、进度、单次重提 |
| 导出 | 即时写入结果 Excel、下载路径 |
| 本地服务 | loopback API、运行状态、进程生命周期 |
| 前端 | 分步动作、逐条结果、日志、下载和滚动跟随 |

模块可以共享明确的数据结构，但不要为了展示架构增加无实际变化原因的层级。HTTP 新 APP 完整独立分发，不从旧 APP 目录运行时导入代码；需要复用时在新 APP 内保留完整实现。

## 单条执行

每条原始记录按以下事实链执行：

1. 在当前动态类型列表中归一输入类型并取得 `limitFlag`、`dateSplitFlag`、描述和默认时间规则。
2. 调用 `vaildStaffNum`，确认权限和门户身份；输入姓名存在时记录一致性。
3. 普通类型原样生成一个提交片段。RECU_LVE/ALV_FD 才读取两类目标年份额度并按旧版智能规则生成零至两个连续片段。
4. 根据时间模式构造结构化 form Body；模式 2 保留重复 `lockDaysNum`。
5. POST 提交并同时解析普通结果与冲突表。
6. 按员工、门户姓名、实际类型、实际起止时间归属当前片段。
7. 每个结果或动作证据立即写 Excel，再处理下一片段或下一人。

HTTP 200 但返回登录页、缺表、字段异常、归属不唯一或类型/日期不匹配，都属于当前记录失败，不能借用响应中的第一行继续。

## 智能路由

保持旧版规则，不扩大到新类型：

- 只有 `RECU_LVE` 和 `ALV_FD` 相互按目标年份可休天数路由。
- 输入类型优先；不足部分使用另一类型的连续尾部日期。
- 两类合计不足时整条不提交。
- 一类额度为零、另一类足够时整段使用另一类。
- 这两类记录不得跨自然年。
- 普通 `ALV`、`RECU_LVE_R` 和其他类型不参与这组互换。

额度响应按表头解析，不按列号。页面没有目标年份数据时如实归档预检失败。

## 冲突恢复

是否启用冲突回退由本批输入选项决定，默认行为与旧 APP 一致。启用后：

1. 保存当前冲突响应。
2. 查询当前员工全分页“已锁”记录。
3. 按员工号、状态和自然日区间重叠筛选，必须唯一。
4. 把候选旧行全部字段和即将执行的动作先写入结果 Excel；保存失败时不解锁。
5. 从唯一候选行读取记录 ID，调用解锁接口并重新查询确认状态。
6. 原 HTTP 提交 Body 只重放一次。
7. 重提仍冲突或失败时停止当前原始记录，不解锁第二条，批量继续下一条。

不能用 checkbox ID、固定序号、行号或接口返回顺序替代唯一业务匹配。新锁班原因继续使用当前输入备注或门户默认原因，不写旧锁班摘要；旧行摘要只写结果证据。

## 本地 API

保留旧工作台可观察契约，名称可按新 APP spec 最终确定：

```text
POST /api/session/verify       验证并装载凭据
POST /api/check-data           数据健康检查，只提示
POST /api/run                  在已验证 Session 中开始当前批次
POST /api/stop                 终止当前批次或服务 worker
GET  /api/status               阶段、日志、进度、逐条结果、下载状态
GET  /api/download/result      下载当前批次结果
POST /api/start                agent 全链路入口
```

`/api/start` 仍需要调用方提供或先装载有效凭据；它可以串联凭据验证、输入检查和运行，但不能模拟登录，也不能替代前端人工分步。服务只监听 `127.0.0.1`。

运行阶段至少区分：等待凭据、验证凭据、凭据有效、检查数据、数据已检查、运行中、已完成、终止中、已终止、失败。阶段用于表达事实，不增加人工确认门槛。

## 前端结果与日志

- 标题明确为“锁班皇帝（新）”，状态区显示当前凭据是否有效，但绝不显示 Cookie。
- 输入仍在 Excel/粘贴之间切换。类型来自每行，不提供整批类型选择器。
- 逐条结果显示员工号、姓名、输入类型/日期、实际类型/日期时间、状态、门户结果、尝试次数、回退信息和备注。
- 勾选直接通过时，逐条结果先显示提交成功，再显示已通过并锁班或通过失败。
- 日志按阶段显示凭据验证、动态类型加载、数据检查、开始处理、逐人结果和完成汇总。
- 结果区和日志区默认自动置底；用户向上滚动后暂停跟随，滚回底部后恢复。
- 一批完成后清空本批输入/结果状态时不清除有效 Session，用户可直接准备下一批。

## 结果与恢复

- 结果写入 `results/<runId>/`，每处理一条或一个片段立即保存，不回写输入 Excel。
- 结果保留原始行、实际片段、动态类型元数据、请求时间模式、门户结果、冲突、匹配证据、动作结果和尝试次数。
- 中断后以结果 Excel 和门户查询状态共同判断完成项；不能仅按内存进度重跑。
- 首段成功、后段失败属于部分完成，恢复时排除成功片段。
- Session 失效时停止新提交并提示重新粘贴凭据；不要自动重试所有已发送请求。

## 测试与探针

仓库测试全部使用虚构人员和脱敏 HTML/JSON fixture，覆盖：

- cURL/Cookie Header 解析和凭据不回显。
- 动态 option 的 code、label、class、id 解析及新增类型。
- `staffNum` 与 `staffnum` 大小写不同的请求契约。
- 模式 1 任意分钟、默认时间、跨日和锁班天数。
- 模式 2 重复 `lockDaysNum`、非连续日期和逐日结果。
- 自定义备注、统一备注和门户默认备注优先级。
- 普通结果、冲突结果、空表和登录页识别。
- 查询表头、分页、状态代码和唯一候选。
- 智能额度双向路由、额度不足和缺年。
- 解锁前证据保存、状态复核、单次重提和重提失败。
- loopback 监听、人工分步、agent 入口、批次结束后 Session 复用。

真实探针只在 owner 当次明确授权后运行。优先只读验证；状态变更测试使用可精确识别的孤立样例，记录实际提交次数，完成后重新查询确认没有遗留待审批或已锁记录。探针、Cookie 和原始响应只放系统临时目录并在收口时删除。
